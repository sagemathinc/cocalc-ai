# Agents dogfood triage (2026-09-23)

## Purpose and baseline

This is a decision queue, not an instruction to implement every note. The source is the maintainer's two-day `agents.tasks` dogfood log (35 active entries, 2 deleted entries). A note is evidence of an experience, not yet a verified root cause or an approved design. Do not copy its private screenshots, conversation URLs, or agent-message contents into a public PR.

This follow-up is stacked on draft [#668](https://github.com/sagemathinc/cocalc-ai/pull/668), head `8e28b41b5e` at triage time. Keep #668 unchanged. Recheck each report against the actual deployed build and this branch before changing code; some observations may be stale, environment-specific, or affected by work already in #668. In particular, #668 includes composer cursor/draft changes and a Library/workbench redesign, but neither proves the remaining reports fixed. No active note is marked resolved without a reproduction or acceptance check.

Use `P0` for a candidate release blocker if reproduced, `P1` for high-friction or trust failures, `P2` for bounded polish, `Decision` for behavior that needs product agreement, and `Hold` for insufficient evidence or a broader design discussion. Priorities are provisional.

## One-at-a-time execution protocol

1. Continue with the runtime-settings and credential P0s. For each item, record the build/commit, route, account/project conditions, steps, expected behavior, actual behavior, and whether #668 already changed it. Mark `fixed already`, `reproduced`, `not reproduced`, `needs decision`, or `deferred`; do not equate a code search with a fix.
2. For a reproduced bug, add a failing focused regression test, make the smallest fix, run the affected package checks and frontend accessibility checks, then verify the human path in browser. Keep each issue in its own commit. Where a report may involve authorization, follow the multibay ownership rules and test the backend boundary rather than only hiding UI.
3. For a product decision, write the smallest proposed behavior and tradeoffs, get maintainer agreement, then implement only the approved slice. Do not treat the note's suggested solution as the requirement.
4. After each accepted slice, update this table with evidence and the commit, then decide whether the next item still matters. Rebase the stacked branch on #668 as needed without pushing changes to #668. Before release, run a targeted smoke matrix: human chat, new/existing agent, dual-open thread, slow initialization, funded model loading, Agent Network live/queued outcomes, and artifact workbench.

The human-chat `To Agent` regression and the dual-composer return path are confirmed fixed. Runtime replacement, credential failures, and funding/mobile configuration remain distinct investigations before model fallback. No broad UX redesign is authorized by this triage document.
